# Day 2 Workshop Plan

**Workshop format**  
2-day OAuth/JWT/FAPI workshop.

**Day 2 focus**  
Move from the OAuth flows (Day 1) to what makes them trustworthy: how tokens are actually
validated, JOSE (JWS/JWE/JWK/JWKS), the common security controls, and the advanced
sender-constraining and request-hardening controls that culminate in FAPI 2.0.

# Day 2 Outcome

By the end of Day 2, participants should be able to:

- Validate a JWT access token conceptually and in practice — signature, issuer, expiry,
  scope — against a JWKS, and explain why decoding is not validation.
- Explain JWS, JWE, and JWK/JWKS without mixing them up, and describe key rotation.
- Connect common OAuth attacks to the controls that stop them.
- Explain why PAR, JAR, JARM, DPoP, and mTLS exist, and what each one protects.
- Explain what FAPI 2.0 is: a profile that combines several controls, not a new protocol.

# Teaching Style

Day 2 is more security-analysis than Day 1. Keep the same rhythm, but lean on threat framing:

1. State the threat (what can leak, replay, or be tampered with).
2. Show the diagram.
3. Run the Go demo and show the control working — and failing when bypassed.
4. Ask participants which control stops which attack.

The Day 2 demos are a single Go module with one runnable example per concept. As on Day 1,
the instructor runs and explains them; participants reason about what happens.

# Implementation Walkthrough Examples

Day 2 implementation examples come from the Go demo module. Run each from the module root
(`resource/labs/day2-oauth-demo`); each starts three servers and is entered at
`http://localhost:8082`.

- Local JWT validation against JWKS, and a tampered token being rejected (`cmd/jwt-validation`).
- A DPoP-bound token accepted with a proof, and a replayed bearer token rejected (`cmd/dpop`).
- A signed request object pushed via PAR, with only an opaque `request_uri` in the browser
  (`cmd/par-jar`).
- The FAPI 2.0 baseline: `private_key_jwt` + PAR + PKCE + DPoP enforced together (`cmd/fapi`).

# Topics Covered in the Papers but Not as Runnable Demos

To keep each lab focused, three topics are taught from the lesson papers and diagrams rather
than as runnable code: **JARM** (Lesson 7), **mTLS** sender-constraining (Lesson 7, the DPoP
alternative), and **JWE** (Lesson 5). Decks 5 and 7 cover these with diagrams.
